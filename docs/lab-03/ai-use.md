## My Reflection - AI-assisted draft for student review

The main lesson from this lab is that authentication changes the whole workflow, not only the login screen. The server must check roles and ticket ownership even when the UI hides an action. The distinction between Public Comments and Internal Notes made this especially clear: private information must be excluded from unauthorized API responses.

Separating the work into issues and pull requests gave each feature a clear review point. The specification established decisions such as staff-only status changes and read-only administrator ticket access before implementation. Coding assistance helped turn those decisions into working screens and tests. Problems such as competing ticket claims and last-administrator changes needed concurrency tests, while the browser checks caught responsive selector and keyboard-access issues that API tests alone could not show.

For future work, I would keep the same specification-first sequence and use both API and browser evidence before considering a feature complete. Short review replies keep the workflow moving, but the detailed test logs and specification links are what make the result easier to verify.
